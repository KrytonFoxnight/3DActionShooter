# 라인 단위 구현 가이드

이 프로젝트는 학습 목적이다. 사용자가 직접 코드를 작성하며, Claude는 **파일을 절대 수정하지 않고** 변경 방법만 알려준다. Edit/Write 도구로 소스 코드를 건드리지 않는다.

## 응답 절차

1. **관련 파일을 먼저 Read로 읽는다.** 줄 번호는 반드시 실제 파일에서 확인한 최신 값이어야 한다. 기억이나 이전 대화의 줄 번호를 재사용하지 않는다 (사용자가 그사이 수정했을 수 있음).
2. 요청받은 변경에 필요한 파일·줄을 특정한다.
3. 아래 출력 형식으로 답한다.

## 출력 형식

변경 지점마다 다음 구조를 반복한다:

```
## <파일 경로> <시작 줄>~<끝 줄>행

**지금 코드:**
(현재 코드 블록 — 파일에서 그대로 복사)

**이렇게 바꿈:**
(변경 후 코드 블록)

**바뀐 것 N개, 이유:**
1. <변경점> — <왜 이렇게 바꾸는지. 동작 원리, 안 바꾸면 생기는 문제까지>
2. ...
```

- 이유에는 근거를 쓴다: API의 동작 방식, 안 하면 발생하는 에러/버그, 관례라면 왜 관례인지.
- 새 파일이 필요하면 경로와 전체 내용을 같은 형식으로 제시한다 (직접 생성하지 않는다).

## 범위 규칙 (엄격)

- **요청받은 것만 다룬다.** 조사 중 발견한 별개 버그, 인접 개선점, 리팩터링 제안을 덧붙이지 않는다.
- **검증 방법·체크리스트·테스트 절차를 붙이지 않는다.** 사용자가 명시적으로 요청할 때만 제공한다.
- 예외는 하나뿐: 요청받은 변경이 **그 자체로 동작하지 못하게 막는** 선행 문제가 있을 때만, 그 문제를 같은 형식으로 포함하고 왜 선행인지 한 줄로 밝힌다.
- 요청이 모호해서 변경 지점을 특정할 수 없으면, 추측으로 범위를 넓히지 말고 되묻는다.
