# Unity 사이드프로젝트 기획 가이드라인

## 1. 프로젝트의 목적

이 사이드프로젝트는 2026년 9~10월경 예상되는 넥토리얼 지원을 염두에 둔 포트폴리오용 데모 프로젝트이다.

핵심 목적은 기존 실무 경험에서 드러나기 어려운 **Unity 엔진 기반 게임플레이 구현 역량**을 공개 가능한 산출물로 보완하는 것이다.

기존 실무 경험은 UGUI 기반 시뮬레이션 게임, MVVM/ViewController 구조, VContainer 기반 의존성 관리, 상점/IAP, 효과 시스템, 테스트 코드, CI/CD, Addressables 이슈 탐지 등 라이브 서비스형 클라이언트 시스템에 강점이 있다.

하지만 향후 3D, 물리, 액션, 전투, 카메라, 애니메이션, 오브젝트 제어가 중요한 프로젝트에 지원할 때는 "Unity 엔진다운 영역을 실제로 다뤄봤는가?"를 보여주는 공개 증거가 부족할 수 있다.

따라서 이 프로젝트는 UI/운영 기능 중심이 아니라, **3D 공간에서 실제로 플레이 가능한 게임 코어**를 먼저 완성하는 것을 목표로 한다.

## 2. 프로젝트 한 줄 정의

**퍼스트 디센던트-lite 구조를 참고한 3D 탑다운 무기 액션 RPG 데모**

또는 포트폴리오용 표현으로는 다음과 같이 정의한다.

> 넥슨게임즈의 3D 액션/루트슈터 타이틀인 퍼스트 디센던트를 구조적 레퍼런스로 삼아,
> 3D 캐릭터 조작, PvE 전투, 스킬 사용, 적 웨이브, 보상 선택 루프를 소규모 탑다운 무기 액션 RPG로 축소 구현한 Unity 포트폴리오 데모이다.

## 3. 왜 이 장르인가

넥슨 최근 주요 타이틀 흐름을 보면 다음 축이 강하다.

- 3D 액션 / 슈터 / 콘솔·PC 지향
  - 퍼스트 디센던트
  - 퍼스트 버서커: 카잔
  - 아크 레이더스
  - 더 파이널스

- 모바일/PC 크로스플랫폼 MMORPG
  - 마비노기 모바일
  - HIT2
  - V4

- 모바일 RPG / 수집형 / 라이브 서비스
  - 블루 아카이브
  - 던전앤파이터 모바일
  - 메이플스토리M

2025년 넥토리얼 기준 Unity/C#과 직접적으로 맞는 포지션은 메이플스토리M, 메이플스토리 월드 계열이었고, 여기서는 신규 콘텐츠/시스템, 유지보수, 최적화, 리팩토링 역량이 중요했다.

다만 사용자의 기존 경험은 이미 UGUI, 상점, 효과 시스템, 테스트, 라이브 서비스 구조 쪽에서 강점이 있다. 따라서 사이드프로젝트는 그 강점을 반복하기보다, 부족하게 보일 수 있는 다음 영역을 보완해야 한다.

- 3D 공간 활용
- 캐릭터 이동
- 물리/충돌/피격 판정
- 카메라 제어
- 애니메이션 상태 전환
- 적 AI
- 웨이브/스폰 시스템
- 플레이 가능한 전투 루프

이 조건을 가장 작고 빠르게 만족시키는 장르가 **3D 탑다운 미니 아레나 액션**이다.

## 4. 고정 레퍼런스: 퍼스트 디센던트-lite

기획을 흔들리지 않게 유지하기 위해, 이 프로젝트의 메인 레퍼런스는 **퍼스트 디센던트**로 고정한다.

단, 원작의 IP, 캐릭터, 아트, UI, 명칭, 세계관을 모방하지 않는다. 여기서 레퍼런스로 삼는 것은 다음과 같은 **구조적 게임 루프**이다.

- 3D 캐릭터 조작
- 활/검 기반 전투
- 스킬 사용
- 적 웨이브 또는 미션 전투
- 전투 후 보상
- 강화된 상태로 다음 전투 진입

원작의 규모를 그대로 따라가면 9월 전 완성이 어렵다. 따라서 이 프로젝트에서는 퍼스트 디센던트의 루트슈터 구조를 아래처럼 축소한다.

```text
퍼스트 디센던트
- 3인칭 루트슈터
- 협동 플레이
- 총기/스킬/보스 공략
- 고품질 3D 비주얼
- 장기 라이브 서비스 구조

사이드프로젝트 버전
- 3D 탑다운 아레나 액션
- 싱글 플레이
- 활 공격 또는 검 공격 + 스킬 2개
- 웨이브 3개 + 미니 보스 1개
- 전투 후 보상 선택
- 3~5분 내외 플레이어블 데모
```

### 프로젝트 가칭

후보 이름:

- `Descendant Arena Lite`
- `Core Arena: Prototype`
- `Project Arena Core`

포트폴리오에서는 넥슨 IP와 혼동되지 않도록, 실제 저장소명과 게임명은 독자적인 이름을 사용한다.

### 고정 게임 루프

```text
타이틀
→ 아레나 진입
→ Wave 1
→ 보상 선택
→ Wave 2
→ 보상 선택
→ Wave 3
→ 미니 보스 또는 강화 적
→ 결과 화면
```

### 플레이어 고정안

플레이어는 활 또는 검을 사용하는 무기 기반 액션 캐릭터 1명으로 고정한다.

구현 요소:

- 3D 탑다운 이동
- 공격 방향 바라보기
- 기본 공격
- 대시
- 스킬 2개
- HP
- 피격
- 사망

### 공격/스킬 고정안

기본 공격:

- 활 선택 시: 마우스 방향 또는 이동 방향으로 화살/에너지 투사체 발사
- 검 선택 시: 전방 부채꼴 또는 짧은 히트박스 공격
- 공격 간격 또는 쿨타임 존재
- 적에게 닿으면 피해 적용

스킬 1: 범위 폭발

- 지정 방향 또는 플레이어 전방에 원형 범위 피해
- 여러 적을 한 번에 처리
- 쿨타임 존재
- 범위 판정과 VFX를 보여주는 용도

스킬 2: 생존/회피형 스킬

- 짧은 무적 대시, 보호막, 넉백 충격파, 또는 대시 베기 중 하나
- 플레이어 생존 로직을 보여주는 용도
- 상태 변화와 쿨타임 처리를 보여준다.

### 적 구성 고정안

적은 9월 전 완성을 위해 최소 수량으로 고정한다.

- 근접 추적형 적 1종
  - 플레이어를 향해 이동
  - 가까워지면 공격
  - 가장 기본적인 전투 대상

- 원거리 공격형 적 1종
  - 일정 거리에서 화살/마법탄 투사체 발사
  - 시간이 부족하면 제외 가능

- 미니 보스 1종
  - HP가 많음
  - 공격 패턴 2개 이하
  - 마지막 웨이브에 등장

### 웨이브 구성 고정안

Wave 1:

- 근접 적 5마리
- 기본 조작과 공격을 익히는 구간

Wave 2:

- 근접 적 8마리
- 원거리 적 2마리, 또는 근접 적만 추가
- 전투 압박 증가

Wave 3:

- 근접 적 다수
- 원거리 적 일부
- 미니 보스 1마리
- 데모의 클라이맥스

### 보상 구조 고정안

웨이브 클리어 후 3개 중 1개 보상을 선택한다.

보상 후보:

- 공격력 증가
- 공격 속도 증가
- 이동속도 증가
- 최대 HP 증가
- 스킬 쿨타임 감소
- 투사체 크기 증가
- 대시 쿨타임 감소

중요한 것은 보상 종류의 수가 아니라, 선택한 보상이 다음 웨이브에서 체감되는 것이다.

### 보조 레퍼런스

메인 레퍼런스는 퍼스트 디센던트로 고정하되, 일부 요소는 다른 넥슨 타이틀을 보조 참고한다.

- 블루 아카이브
  - 캐릭터 스킬, 수집형 RPG, 풀 3D 전투 감각 참고
  - 단, UI/수집/편성 중심으로 흐르지 않도록 주의

- HIT2 / V4
  - 3D 캐릭터 전투, 필드 전투, 모바일/PC RPG 감각 참고
  - 단, MMORPG 구조는 범위가 너무 크므로 따라가지 않음

- 던전앤파이터 모바일
  - 짧은 전투 루프, 스킬 쿨타임, 액션 RPG 보상 감각 참고
  - 단, 2D/벨트스크롤 구조를 메인으로 삼지는 않음

- 퍼스트 버서커: 카잔
  - 보스 패턴, 회피, 피격 긴장감 참고
  - 단, 하드코어 액션 완성도를 목표로 삼지는 않음

### 레퍼런스 고정 원칙

기획이 흔들릴 때는 다음 원칙을 따른다.

- 메인 루프는 퍼스트 디센던트-lite에서 벗어나지 않는다.
- 장르는 3D 탑다운 무기 액션 RPG로 유지한다.
- 싱글 플레이 3~5분 데모를 목표로 한다.
- 보스, 장비, 상점, 인벤토리, 스토리는 확장 요소일 뿐 핵심이 아니다.
- 9월 전 완성을 방해하는 기능은 제외한다.

### 에셋 방향 고정

총기 슈터 전용 애니메이션을 맞추는 데 시간을 쓰기보다, 현재는 활/검 전투를 포괄하는 RPG 액션 애니메이션 팩에 맞춰 기획을 조정한다.

권장 조합:

- 캐릭터/환경: `POLYGON - Battle Royale Pack` 또는 동일 계열 Synty 아트팩
- 모션: `RPG Character Mecanim Animation Pack`
- 부족한 특수 모션: Mixamo 보강

기획상 퍼스트 디센던트에서 가져오는 것은 총기 자체가 아니라 **PvE 전투 → 보상 → 강화 → 다음 전투**의 구조이다. 실제 구현은 활/검/스킬 기반의 3D 탑다운 액션 RPG로 진행한다.

## 5. 프로젝트 범위 원칙

9월 전까지 데모 완성이 목표이므로 범위를 강하게 제한한다.

오늘 기준 2026-07-15이며, 2026-08-31까지 약 47일, 약 6.7주가 남아 있다.

따라서 목표는 "많은 기능이 있는 게임"이 아니라, **작지만 완성된 플레이어블 데모**이다.

### 반드시 지킬 원칙

- 먼저 플레이 가능한 게임 코어를 만든다.
- UI, 상점, 인벤토리, 라이브 서비스 기능은 후순위로 둔다.
- 콘텐츠 양보다 게임 루프의 완결성을 우선한다.
- 영상으로 보여줄 수 있는 장면을 우선한다.
- 9월 전에는 GitHub README, 플레이 영상, 코드 샘플까지 준비되어야 한다.

### 1차 데모에서 제외하거나 최소화할 것

- 복잡한 상점
- IAP 구조
- Firestore 연동
- Mock API
- 우편함
- 출석 보상
- 깊은 인벤토리
- 복잡한 효과 시스템
- 많은 캐릭터/무기
- 보스 여러 종
- Addressables 고도화
- CI/CD 풀세팅

이 요소들은 사용자가 이미 실무에서 설명 가능한 영역이거나, 9월 전 완성을 방해할 수 있는 확장 기능이다.

## 6. 1차 MVP 목표

### 핵심 목표

3D 아레나에서 플레이어가 이동하고, 적을 공격하고, 적의 공격을 피하거나 맞고, 웨이브를 클리어하고, 보상을 선택해 다음 웨이브로 진행하는 짧은 게임 루프를 완성한다.

### MVP 완료 기준

아래 조건을 만족하면 1차 데모로 본다.

- 플레이어가 3D 공간에서 이동한다.
- 카메라가 플레이어를 자연스럽게 따라간다.
- 플레이어가 기본 공격을 할 수 있다.
- 적이 플레이어를 추적한다.
- 적과 플레이어가 서로 피해를 주고받는다.
- 적이 사망한다.
- 플레이어가 사망한다.
- 웨이브가 순차적으로 진행된다.
- 웨이브 클리어 후 보상을 선택할 수 있다.
- 최종 웨이브 클리어 또는 플레이어 사망 시 결과 화면이 나온다.
- 실행 영상으로 플레이 루프를 설명할 수 있다.

## 7. 핵심 시스템 목록

### 7.1 플레이어 시스템

구현 범위:

- 3D 탑다운 이동
- 조준 또는 공격 방향 결정
- 기본 공격
- 대시 또는 회피
- HP
- 피격
- 사망

포트폴리오 어필 포인트:

- Unity 3D 공간에서 캐릭터를 직접 제어한다.
- 입력, 이동, 공격, 피격 상태를 분리한다.
- 카메라와 조작감이 맞물리도록 구성한다.

### 7.2 카메라 시스템

구현 범위:

- 플레이어 follow
- 고정 탑다운 또는 사선 탑다운 시점
- 부드러운 추적
- 간단한 카메라 shake

포트폴리오 어필 포인트:

- UGUI 중심 경험으로는 드러나지 않는 엔진 기반 연출을 보여준다.
- 전투 상황에서 시야와 조작감을 고려한다.

### 7.3 전투 판정 시스템

구현 범위:

- 히트박스/허트박스
- 충돌 또는 트리거 기반 피격 판정
- 공격 쿨타임
- 피격 무적 시간 또는 중복 피격 방지
- 사망 처리

포트폴리오 어필 포인트:

- Unity Physics/Collider/Trigger 기반의 상호작용을 다룬다.
- 전투 판정을 UI나 단순 수치 계산이 아니라 월드 오브젝트 상호작용으로 구현한다.

### 7.4 적 AI 시스템

구현 범위:

- 근접 적 1종
- 가능하면 원거리 적 1종
- 플레이어 추적
- 공격 거리 판단
- 공격 후 딜레이
- 사망 처리

포트폴리오 어필 포인트:

- 단순한 AI라도 상태 전환 구조를 보여준다.
- 추적, 공격, 대기, 사망 상태를 명확히 나눈다.

### 7.5 웨이브/스폰 시스템

구현 범위:

- 웨이브 3개
- 웨이브별 적 수/종류 설정
- 스폰 위치 관리
- 웨이브 클리어 판정
- 다음 웨이브 진입

포트폴리오 어필 포인트:

- 게임 진행 상태를 구조적으로 관리한다.
- 데이터 기반 웨이브 구성을 확장할 여지를 남긴다.

### 7.6 보상/성장 시스템

구현 범위:

- 웨이브 클리어 후 보상 선택

- 선택한 보상이 다음 웨이브에 반영

추천 보상 예시:

- 공격력 증가
- 이동속도 증가
- 최대 HP 증가
- 공격 쿨타임 감소
- 공격 범위 또는 투사체 크기 증가

포트폴리오 어필 포인트:

- 전투와 성장의 연결을 보여준다.
- 향후 상점/인벤토리/효과 시스템으로 확장할 수 있다.

### 7.7 오브젝트 풀링

구현 범위:

- 투사체 또는 피격 이펙트 풀링
- 적 스폰 풀링은 가능하면 추가

포트폴리오 어필 포인트:

- 런타임 Instantiate/Destroy 남발을 줄이는 최적화 의식을 보여준다.
- 액션 게임에서 생성/제거 비용을 관리한다.

```md
# 3D Top-down Arena Action Demo

이 프로젝트는 2026 넥토리얼 Unity/C# 클라이언트 직무 지원을 대비하여 제작한 포트폴리오용 Unity 데모입니다. 넥슨게임즈의 퍼스트 디센던트를 구조적 레퍼런스로 삼되, 총기 슈터가 아니라 3D 탑다운 무기 액션 RPG 형태로 범위를 축소했습니다.

기존 실무에서는 UGUI 기반 시뮬레이션 게임, MVVM/ViewController 구조, 상점/IAP, 효과 시스템, 테스트 코드, CI/CD 등 라이브 서비스형 클라이언트 시스템을 주로 담당했습니다.

이 프로젝트에서는 해당 경험으로 드러나기 어려운 Unity 엔진 기반 게임플레이 구현 역량을 보완하기 위해, 3D 탑다운 액션 전투 루프를 직접 구현했습니다.

주요 구현 요소는 다음과 같습니다.

- 3D 캐릭터 이동
- 카메라 추적
- 활/검 기반 공격/피격 판정
- 적 AI
- 웨이브 스폰
- 보상 선택
- 간단한 성장 구조
- Object Pooling

레퍼런스 방향:

- 퍼스트 디센던트의 PvE 전투, 스킬, 보상 루프를 활/검 기반 소규모 싱글 플레이 데모로 재해석
- 원작 IP/아트/UI가 아니라 게임플레이 구조만 참고
```

## 14. 최종 결론

이 사이드프로젝트의 1차 목표는 완성도 높은 거대한 게임이 아니다.

목표는 다음 한 문장으로 정리된다.

> UGUI 기반 실무 경험으로는 드러나기 어려운 Unity 엔진 기반 게임플레이 구현력을, 9월 전까지 플레이 가능한 3D 탑다운 액션 데모로 증명한다.

따라서 개발 우선순위는 항상 다음 순서를 따른다.

1. 3D 게임플레이 코어 완성
2. 전투 루프 완성
3. 영상으로 보이는 완성도 확보
4. README/코드 샘플/회고 문서화
5. 남는 시간에 보조 시스템 추가
